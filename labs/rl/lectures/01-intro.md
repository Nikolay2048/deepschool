# Лекция 01. Что такое reinforcement learning

## Зачем вообще нужен RL

Reinforcement learning, или обучение с подкреплением, нужен там, где модель должна не просто предсказать ответ, а **научиться действовать**.

В supervised learning у нас обычно есть пары:

```text
input -> correct answer
```

Например:

```text
картинка кота -> label "cat"
текст письма -> spam / not spam
история покупок -> вероятность покупки
```

В RL ситуация другая. Агент делает действия, получает последствия, а затем постепенно учится выбирать действия лучше.

```text
state -> action -> reward -> next state
```

Примеры задач:

- агент играет в игру;
- робот учится ходить;
- торговая стратегия выбирает действие: купить, продать, ждать;
- рекомендательная система выбирает, что показать пользователю;
- LLM-агент выбирает, каким инструментом воспользоваться;
- система учится управлять ресурсами: CPU, память, очередь задач.

Главная идея: **нет готового правильного ответа на каждый шаг**. Есть только обратная связь после действия.

## Базовые элементы RL

В RL почти всегда есть несколько ключевых сущностей.

### Agent

Агент - тот, кто принимает решения.

Например:

- игрок в игре;
- робот;
- торговый бот;
- LLM-агент;
- алгоритм, выбирающий рекламу.

### Environment

Среда - мир, в котором агент действует.

Среда:

- показывает агенту текущее состояние;
- принимает действие агента;
- возвращает новое состояние;
- возвращает награду;
- сообщает, закончился ли эпизод.

Типичный интерфейс можно представить так:

```python
state = env.reset()
next_state, reward, done, info = env.step(action)
```

### State

State, или состояние, - информация о текущей ситуации.

Примеры:

- позиция персонажа в игре;
- координаты робота и скорость суставов;
- текущая доска в шахматах;
- последние сообщения в диалоге агента;
- признаки пользователя в рекомендательной системе.

Важно: состояние не всегда содержит весь мир. Иногда агент видит только наблюдение. Тогда говорят не `state`, а `observation`.

### Action

Action - действие, которое выбирает агент.

Примеры:

- пойти влево, вправо, прыгнуть;
- купить, продать, ничего не делать;
- выбрать документ для retrieval;
- вызвать инструмент;
- сгенерировать следующий токен.

Действия бывают:

- дискретные: `left`, `right`, `jump`;
- непрерывные: угол поворота руля, сила мотора, координаты движения.

### Reward

Reward - численная награда за действие или его последствия.

Примеры:

- `+1` за победу;
- `-1` за смерть;
- `+0.1` за продвижение к цели;
- `-0.01` за каждый шаг, чтобы агент не тянул время;
- `+1` за клик пользователя;
- `-10` за опасное действие.

Reward - это не всегда "хорошая" метрика. Очень часто самая сложная часть RL - правильно задать награду.

Если награда задана плохо, агент может научиться странному поведению. Это называется reward hacking.

## Главный цикл RL

Один шаг выглядит так:

```text
1. Среда дает состояние s.
2. Агент выбирает действие a.
3. Среда применяет действие.
4. Агент получает reward r.
5. Среда возвращает новое состояние s'.
6. Агент обновляет свою стратегию.
```

В псевдокоде:

```python
state = env.reset()

while not done:
    action = agent.choose_action(state)
    next_state, reward, done, info = env.step(action)
    agent.learn(state, action, reward, next_state, done)
    state = next_state
```

Это почти вся механика RL. Дальше разные алгоритмы отличаются тем, **как именно агент выбирает действие** и **как именно он учится по reward**.

## Policy

Policy - стратегия агента.

Она отвечает на вопрос:

```text
Что делать в этом состоянии?
```

Формально:

```text
policy(state) -> action
```

Или, если стратегия вероятностная:

```text
policy(state) -> probability distribution over actions
```

Например, в состоянии `s` агент может выбрать:

```text
left:  10%
right: 70%
jump:  20%
```

В начале обучения policy обычно плохая. Агент пробует действия, получает опыт и постепенно улучшает policy.

## Exploration vs exploitation

Это один из центральных конфликтов RL.

**Exploitation** - использовать то, что уже кажется лучшим.

**Exploration** - пробовать новое, чтобы найти что-то лучше.

Пример: ты выбираешь кафе.

- exploitation: пойти в знакомое кафе, где точно нормально;
- exploration: попробовать новое место, которое может быть лучше или хуже.

Если всегда exploit - можно застрять на посредственном решении.

Если всегда explore - не будешь использовать уже найденные хорошие решения.

RL постоянно балансирует между этими режимами.

## Episode

Episode - один законченный проход взаимодействия агента со средой.

Примеры:

- одна партия в игре;
- один запуск робота до падения или достижения цели;
- один диалог агента с пользователем;
- один маршрут до цели.

Эпизод заканчивается, когда `done = True`.

Но не все задачи эпизодические. Иногда задача продолжается бесконечно, например управление сервером или рекомендациями.

## Return

Return - суммарная будущая награда.

Если агент получил награды:

```text
r1 = 1
r2 = 0
r3 = 5
```

то простой return:

```text
G = 1 + 0 + 5 = 6
```

Но часто будущие награды дисконтируют:

```text
G = r1 + gamma * r2 + gamma^2 * r3 + ...
```

`gamma` - discount factor, обычно число от `0` до `1`.

Если `gamma` близко к `0`, агент думает почти только о ближайшей награде.

Если `gamma` близко к `1`, агент сильнее учитывает далекое будущее.

## Почему RL сложнее обычного supervised learning

Есть несколько причин.

### Нет правильных ответов

В supervised learning есть target. В RL есть только reward, иногда сильно отложенный.

Агент может сделать хороший ход сейчас, но награду получить через 100 шагов.

### Данные зависят от агента

В supervised learning dataset обычно фиксирован.

В RL агент сам собирает данные. Если policy плохая, данные тоже будут плохими.

### Exploration может быть дорогим

Чтобы научиться, агент должен пробовать. Но в реальном мире ошибки могут стоить денег, времени или безопасности.

### Награда может быть редкой

Например, в игре агент получает `+1` только за победу и `0` за все остальные действия.

Тогда он долго не понимает, какие действия полезны.

## Первый практический объект: multi-armed bandit

Мы начнем не с игр и не с нейросетей, а с простой задачи: multi-armed bandit.

Представь несколько игровых автоматов. У каждого автомата своя неизвестная средняя награда.

На каждом шаге ты выбираешь один автомат и получаешь награду.

Цель - максимизировать суммарную награду.

Почему это хороший старт:

- нет сложных состояний;
- легко увидеть exploration vs exploitation;
- можно написать с нуля на Python;
- это основа для понимания более сложных RL-алгоритмов.

В bandit-задаче нет полноценного `state`. Есть только выбор действия и reward.

```text
action -> reward
```

Именно поэтому это самый мягкий вход в RL.

## Что нужно понять из этой лекции

Минимальный набор:

- RL - это обучение действиям через награды.
- Агент взаимодействует со средой.
- Агент выбирает action на основе state.
- Среда возвращает reward и next_state.
- Policy - стратегия выбора действий.
- Exploration vs exploitation - главный конфликт на старте.
- Episode - один законченный проход.
- Return - суммарная будущая награда.
- Начинать удобно с multi-armed bandit.
