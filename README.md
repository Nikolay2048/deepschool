# DeepSchool

Личная AI-лаборатория для экспериментов из любопытства: трансформеры, RAG, RL, агенты, мультимодальность и любые другие технологии, которые захочется потрогать руками.

Проект не обязан быть строгим исследовательским репозиторием. Главная цель - быстро пробовать идеи, сохранять полезные находки и постепенно собирать свою карту понимания.

## Структура

```text
.
|-- labs/             # тематические зоны для более осмысленных экспериментов
|   |-- transformers/
|   |-- rag/
|   |-- rl/
|   |-- agents/
|   |-- multimodal/
|   `-- misc/
|-- notes/            # личные заметки, вопросы, конспекты, ссылки
|-- prompts/          # промпты, системные инструкции, eval-примеры
|-- snippets/         # маленькие куски кода и одноразовые утилиты
|-- assets/           # тестовые тексты, pdf, картинки, маленькие датасеты
|-- outputs/          # результаты запусков, временные файлы, логи
|-- playground/       # совсем свободная песочница
|-- Seminars/         # учебные материалы, которые уже были в проекте
|-- README.md
`-- requirements.txt
```

## Темы в `labs`

- `transformers/` - attention, tokenizers, tiny GPT, training loops, inference.
- `rag/` - chunking, embeddings, vector search, reranking, eval.
- `rl/` - bandits, Gymnasium, policy gradients, PPO, reward design.
- `agents/` - tools, planning, memory, multi-agent workflows.
- `multimodal/` - vision, audio, OCR, VLM-пайплайны.
- `misc/` - все, чему пока рано давать отдельную полку.

## Быстрый старт

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Как добавлять новую пробу

Если идея маленькая и хаотичная - клади ее в `playground/`.

Если тема уже понятна - создай папку внутри подходящего раздела `labs/`:

```text
labs/
`-- rag/
    `-- first-vector-search/
        |-- README.md
        |-- notebook.ipynb
        `-- run.py
```

В README достаточно коротко написать:

- что хотел проверить;
- что запустить;
- что получилось;
- что хочется попробовать дальше.

## Правила хранения

- `outputs/` - для временных результатов, логов, чекпоинтов и всего, что можно пересоздать.
- `assets/` - для небольших входных файлов, которые удобно держать рядом с кодом.
- Крупные модели, датасеты и логи лучше не коммитить.
- Когда кусок кода начинает повторяться, можно перенести его в `snippets/` или сделать маленькую утилиту рядом с конкретной темой.
