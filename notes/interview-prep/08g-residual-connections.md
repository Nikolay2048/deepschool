# Residual connection: зачем прибавлять вход

Практика: [notebook 06](../../Seminars/transformers/06-residual-connections.ipynb).

## 1. Одна новая операция

Обычная ветвь выдаёт y=F(x). Residual-вариант выдаёт y=x+F(x). F — не особая функция PyTorch, а обозначение преобразования: например, нашего attention. Вход x проходит по прямому пути, а ветвь добавляет свой результат.

Для x=[2,-1,3] и F(x)=[0.5,1,-1] получаем y=[2.5,0,2]. Складываем соответствующие координаты, а не склеиваем векторы. Длина остаётся 3.

## 2. Зачем такой путь

Представим, что на некотором этапе полезно почти не менять текущее представление. Без residual ветви пришлось бы научиться воспроизводить вход. С residual достаточно научиться выдавать результат, близкий к нулю. Поэтому ветвь удобно рассматривать как обучаемое изменение текущего представления.

Если F(x)=0, то y=x. Но это не означает, что вход всегда можно восстановить из y при любых F. Например, F(x)=-x даёт y=0. Прямой путь не гарантирует безусловное сохранение информации. F(x) также не обязано быть небольшим по величине.

Residual не выбирает автоматически, когда «выключать слой»: результат ветви определяется её параметрами и входом. Он обучается вместе с остальной моделью через общий loss.

## 3. Почему сложение, а не cat

В multi-head attention cat сохранял отдельные группы признаков голов перед выходной проекцией. Здесь другая задача: прибавить изменение к текущему представлению той же позиции, сохранив его размерность.

У нашей attention-модели вход и выход (B,T,D). Поэтому x+attention(x) складывает векторы одних и тех же позиций. Для residual требуем одинаковые формы, даже если PyTorch технически допускает некоторые варианты broadcasting: случайное расширение осей может скрыть ошибку. При несовпадающих размерностях иногда используют отдельную проекцию прямого пути; сейчас это не нужно.

## 4. Что происходит с градиентом

Для одного числа y=x+F(x) производная dy/dx=1+F'(x). Единица возникает из прямого слагаемого x. Если F(x)=0.1*x, получаем 1.1 вместо 0.1 без residual.

Для конечного loss цепное правило даёт dL/dx = dL/dy * (1+F'(x)). Для векторов вместо единицы используется единичная матрица в якобиане. Пока достаточно скалярной интуиции: существует путь градиента, который не умножается на производную самой ветви F.

Это помогает оптимизации глубоких моделей, но не гарантирует ненулевые или большие градиенты всегда: возможны нулевой внешний градиент, компенсация вкладов и другие эффекты. Например, F'(x)=-1 обнулит суммарную производную.

Градиенты по параметрам F тоже остаются. В опыте с нулевым Linear без bias его выход равен нулю, но изменение веса меняет этот выход; поэтому общий loss может иметь ненулевую производную по весу. Backward вычисляет её, но не обновляет вес без optimizer.step(). Не переносим вывод о простой линейной ветви на любую нелинейную архитектуру.

## 5. Место в будущем Transformer-блоке

Наш готовый attention станет одной из ветвей. Для выбранного pre-norm варианта позже будет:

```python
x = x + attention(norm_1(x))
x = x + mlp(norm_2(x))
```

Сегодня не нужно писать или запоминать весь блок. Следом разберём нормализацию, затем MLP и соберём их с готовым attention. Важно только заметить: прямой путь содержит текущий x, а нормализация находится внутри преобразуемой ветви.

Если attention причинный, а сложение выполняется для соответствующих позиций, residual не добавляет доступа к будущим токенам. Прямой вход также должен быть причинным: нельзя исправить маской утечку, уже попавшую в x.

## 6. Короткий ответ

> Residual connection вычисляет y=x+F(x). Она позволяет ветви обучать изменение входного представления и создаёт прямой путь для передачи сигнала и градиента. При нулевом результате ветви блок возвращает вход. Это помогает обучению глубоких моделей, но не является гарантией отсутствия затухания градиентов или потери информации.
