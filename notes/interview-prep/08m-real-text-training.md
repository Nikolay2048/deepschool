## 3. Разделяем главы, а не случайные перекрывающиеся окна

Используем:

- I–X: train, параметры обновляются на этих данных;
- XI–XII: validation, выбираем сохранённые веса;
- XIII–XIV: test, откладываем до финальной оценки.

Если сначала нарезать перекрывающиеся окна и случайно разделить их, почти одинаковые участки могут оказаться в train и validation. Метрика будет излишне оптимистичной. Поэтому сначала разделяем исходные главы, затем отдельно строим окна.

Это не гарантирует полной независимости частей: книга одна, персонажи и стиль общие; главы различаются по содержанию. Такой split оценивает перенос на отложенные главы этой книги, не на весь русский язык.

Test не используем для выбора learning rate, числа шагов, словаря или удачного образца генерации. Иначе он перестаёт быть финальной независимой оценкой.

## 4. Словарь по train и неизвестные символы

Для первого опыта приводим текст к нижнему регистру и Unicode NFC. Пунктуацию и абзацы сохраняем. Исходные файлы не меняются; обработка происходит в памяти.

```python
tokens = ['<unk>'] + sorted(set(train_text))
```

ID 0 означает неизвестный символ. Остальные ID задаются упорядоченным списком символов train. На validation словарь не расширяем: незнакомый знак превращается в 0.

Это компромисс. Утраченное различие редких символов влияет на интерпретацию loss. Поэтому выводим долю неизвестных символов. При генерации ID 0 показываем как знак замены �, а не выдаём его за букву.

Если повторять опыт с другой обработкой регистра или Unicode, получится другой словарь. Поэтому сохранение только весов без словаря и правил обработки недостаточно.

## 5. Твоё задание в подготовке batch

Входное окно начинается в i:

```python
x = data[i:i + T]
y = data[i + 1:i + T + 1]
```

Из T+1 символов получаем T задач предсказания. Для batch несколько таких окон объединяются через torch.stack. Форма обоих тензоров (B,T). Во вход не нужно добавлять последний target.

Модель по-прежнему получает контекст causal attention; изменение текста не меняет смысл маски.

## 6. Обучение знакомое

Твой train_step переносится из урока 08:

```python
optimizer.zero_grad(set_to_none=True)
logits = model(x)
loss = F.cross_entropy(logits.reshape(-1, V), y.reshape(-1))
loss.backward()
optimizer.step()
```

Обучаем заново, а не загружаем веса синтетической модели. Словарь другой, смысл ID другой. Все параметры, включая embeddings, стартуют с новой инициализации.

Каждые 100 шагов оцениваем train/validation на фиксированных наборах окон. Это выборочная оценка; одинаковые окна облегчают сравнение между шагами, но многократный подбор по ним может подстроиться к validation.

Если train снижается, а validation растёт, это повод проверить переобучение и выбор момента остановки. Не увеличиваем число шагов бесконечно только ради красивого train loss. Анализируем реальные логи.

## 7. Лучшие и последние веса — не одно и то же

В папке запуска два файла:

- best.pt — состояние с минимальным наблюдавшимся validation loss;
- last.pt — состояние после последнего завершённого цикла.

Например, у шага 700 validation мог быть лучше, чем у шага 1000. Тогда best.pt содержит шаг 700. Исходное состояние на шаге 0 тоже сохраняем как начального кандидата, чтобы честно отразить отсутствие улучшения, если оно произойдёт.

Для каждого нового запуска создаём уникальную папку с датой и случайным суффиксом. Новая модель не затирает прежний опыт. Повтор только цикла продолжает текущую модель и обновляет файлы внутри её папки.

## 8. Что такое state_dict

```python
model.state_dict()
```

Возвращает отображение имён параметров и сохраняемых buffers на тензоры. Это значения модели, а не Python-код класса.

Checkpoint содержит:

- model_state — эти тензоры;
- model_config — D, число блоков и голов, размер словаря, контекст;
- tokens — упорядоченный словарь;
- step и metrics — откуда взяты веса;
- history — замеры к моменту сохранения;
- source, хеш данных, preprocessing и split — контекст опыта.

Перед сохранением тензоры копируются на CPU. detach отделяет их от графа, clone создаёт отдельную копию. Это не изменяет обучаемые параметры исходной модели.

## 9. Загрузка — две отдельные операции

```python
checkpoint = torch.load(path, map_location='cpu', weights_only=True)

restored_model = TinyLanguageModel(**checkpoint['model_config'])
restored_model.load_state_dict(checkpoint['model_state'])
restored_model = restored_model.to(DEVICE)
restored_model.eval()
```

Первая операция создаёт архитектуру. Вторая загружает в неё значения параметров. Случайная инициализация нового объекта заменяется сохранёнными тензорами.

Оператор ** перед словарём передаёт пары ключ–значение как именованные аргументы конструктора. Например, {'d_model':32} становится d_model=32.

Использовать словарь символов другого запуска нельзя: формы могут совпасть, но смысл строк embeddings и координат logits станет другим. Для генерации передаём checkpoint['tokens'].

Загружать следует только свои доверенные файлы. weights_only=True ограничивает десериализацию, но не является универсальной гарантией безопасности неизвестного файла.

## 10. Это сохранение для генерации, не полное возобновление обучения

Для точного продолжения Adam недостаточно model.state_dict. Нужны также состояние optimizer, счётчики, состояния генераторов случайных чисел и, при наличии, scheduler/scaler. В этом уроке их не сохраняем, чтобы не добавлять ещё одну большую тему.

Поэтому после загрузки можно генерировать. Можно создать новый optimizer и обучать дальше, но это новый процесс оптимизации, не точное продолжение прежнего Adam.

Внутри текущего kernel повтор цикла сохраняет существующее состояние Adam, пока не переисполнена ячейка его создания.

## 11. Что прислать

Сначала можно прислать A: формы, сдвиг и два ответа. После B/C нужны:

- loss до обучения и метрики выбранной модели;
- шаг best.pt;
- генерация загруженной модели;
- ответы о словаре и сохранении.

Сгенерированный текст оцениваем вместе с loss; один удачный фрагмент не доказывает качество. Весь test оставляем на позднюю финальную оценку.

## 12. Короткий ответ для собеседования

Для инференса создаю такой же класс модели и загружаю state_dict. Для точного возобновления обучения понадобилось бы дополнительно сохранить optimizer и состояния случайности.

## 13. Разбор первого неудачного текста и улучшение

Первый запуск ученика: train loss 4.50503 → 2.51866, validation 4.50124 → 2.51920 за 1000 шагов. Заполненные targets и загрузка state_dict правильные. Ментор воспроизвёл результат и проверил сдвиг, причинность, неизменность входа, конечность градиентов и совпадение logits после загрузки checkpoint. Ошибка в этих компонентах не обнаружена.

Сначала увеличили только длительность обучения маленькой модели, сохранив её Adam: к 10 000 шагам train=1.97235, validation=1.98655. Значит, 1000 шагов действительно было недостаточно даже для этой небольшой конфигурации. Генерация, однако, оставалась слабой.

Затем обучили с нуля один более крупный профиль: D=128, d_ff=512, два блока, четыре головы, контекст 128, lr=0.0003, 6000 шагов. Это 431 360 параметров. Одновременно изменено несколько настроек, поэтому нельзя приписывать всё улучшение одному размеру или контексту.

| Опыт | Шаги | Validation на одинаковых окнах длины 32 |
|---|---:|---:|
| Маленькая модель, первый запуск | 1000 | 2.51920 |
| Та же маленькая модель, продолжение | 10 000 | 1.98655 |
| Более крупный профиль | 6000 | 1.76137 |

На своих оценочных окнах длины 128 крупный профиль получил train=1.58632, validation=1.76880. Это другие окна/условия оценки; не смешиваем их с колонкой выше. Использован один seed, статистическую значимость не измеряли. Test XIII–XIV не оценивался. Журналы отдельных запусков находятся в локальных runs.

### Почему даже улучшенная модель ошибается

Loss усредняется по предсказаниям с правильными предыдущими символами из корпуса. При генерации модель использует собственные символы, поэтому ошибки становятся новым контекстом и могут накапливаться. Низкая средняя ошибка не гарантирует грамматику, связность или сюжет.

Одна книга, короткий контекст и небольшая посимвольная модель — ограничения этого учебного опыта. В образце появились настоящие слова и имена, но остаются выдуманные слова и бессмысленные фразы. Не называем результат связной прозой и не оцениваем способности ученика по литературному качеству модели.

### Temperature — не дополнительное обучение

В разделе D сравниваются temperature=1 и 0.8 при одинаковом prompt и seed. Деление logits на 0.8 делает распределение более концентрированным: вероятные символы выбираются чаще. Это иногда снижает случайные ошибки, но может усиливать повторы. Параметры модели и исходный validation loss не меняются.

### Что теперь делать ученику

Не переписывать ещё раз весь код и не увеличивать число шагов вслепую. Сначала посмотреть сохранённые результаты D и разобрать ответы, добавленные под исходными вопросами. Для генерации использовать улучшенный checkpoint, а не снова запускать ячейку создания случайной модели. Изучение отдельных настроек продолжим после этого.

Статус: baseline и ограниченные эксперименты исполнены ментором с явного разрешения пользователя. Исходные решения сохранены, к ноутбуку добавлен отдельный улучшенный профиль и пояснения. Это разрешение относится к уроку 09, а не к автоматическому запуску всех будущих ноутбуков.
