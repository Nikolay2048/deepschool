# Векторизованный causal multi-head attention

Практика: [notebook 05c](../../Seminars/transformers/05c-vectorized-attention.ipynb). Подготовка: [оси голов](08e-head-axes.md).

## 1. Что меняется

Раньше forward перебирал H отдельных голов. Теперь Q/K/V вычисляются тремя общими Linear(D,D), затем представляются в форме (B,H,T,head_dim). Математика та же, но Python-цикл по головам в новом forward не нужен. Не путай три отдельные общие проекции Q/K/V с единственным слоем D→3D: объединять их в один слой в этом уроке не будем.

## 2. Как получить одинаковые веса

У каждой прежней Query-проекции weight формы (head_dim,D), где строки соответствуют выходным признакам. Склеивание по строкам через cat(...,dim=0) даёт (H*head_dim,D)=(D,D). Первые head_dim строк принадлежат голове 0, следующие — голове 1 и так далее.

После X @ W.T результат (B,T,D) содержит выходные признаки голов рядом. reshape(B,T,H,head_dim) выделяет группы, transpose(1,2) даёт (B,H,T,head_dim). Аналогично для K/V.

В отличие от cat весов по строкам, выходы отдельных голов склеивались по последней оси признаков. Оси разных тензоров имеют разный смысл — dim нельзя выбирать только по памяти о предыдущем вызове.

Одинаковый seed не гарантирует соответствующих весов у разных архитектур: отличаются формы слоёв, порядок их создания и расход случайных чисел. В тесте явно копируем соответствующие веса и выходную проекцию. copy_ выполняем под no_grad, сохраняя существующие объекты параметров.

## 3. Все головы в одном матричном умножении

```python
scores = (q @ k.transpose(-2, -1)) / math.sqrt(self.head_dim)
```

Последние две оси — матрицы, ведущие B/H задают независимые пары для умножения. Результат (B,H,T,T): для каждой последовательности, каждой головы и каждой Query есть веса по T источникам.

```python
positions = torch.arange(x.shape[1], device=x.device)
blocked = positions[None, :] > positions[:, None]
weights = torch.softmax(scores.masked_fill(blocked, float('-inf')), dim=-1)
context_heads = weights @ v
```

Маска (T,T) распространяется по B/H, головы не смешиваются. softmax нормирует источники отдельно для каждой Query каждой головы. Делим на sqrt(head_dim), потому что каждое скалярное произведение имеет head_dim слагаемых, не D.

## 4. Возвращаем результаты в D

context_heads имеет форму (B,H,T,head_dim). Возвращаем позиции перед головами, объединяем признаки и применяем выходную проекцию:

```python
batch_size, length, _ = x.shape
combined = context_heads.transpose(1, 2).reshape(batch_size, length, self.d_model)
return self.output_projection(combined)
```

После transpose тензор может быть non-contiguous. reshape при необходимости делает копию. Прямой reshape без обратной перестановки может сохранить ожидаемую форму, но неправильно смешать позиции и головы.

## 5. Проверки по этапам

A: общие Q/K/V сравниваются со stack выходов отдельных проекций. Это локализует ошибки переноса весов или осей до вычисления attention.

B: полный forward сравнивается с эталоном на разных B/T, включая T=1. Проверяется причинность через изменение будущего.

C: сравниваются градиенты по входу и соответствующим параметрам. Равенства выхода недостаточно: например, ошибочный detach может сохранить числа forward, но оборвать градиенты. Порядок операций с плавающей точкой может давать небольшие различия округления, поэтому используем assert_close с допуском.

Искусственный loss проверяет механику, а не качество языка. Optimizer.step здесь отсутствует. Проверки конкретных примеров не являются доказательством всех возможных свойств модели.

## 6. Параметры и производительность

Три матрицы (D,D) и выходная (D,D) без bias дают 4*D*D параметров, как у прежней модели. При D=8 это 256. Количество отдельных тензоров параметров изменилось, количество скалярных параметров — нет.

Устранение Python-цикла может помочь производительности, но ускорение надо измерять на одинаковых устройстве, dtype, B/T/D/H и режиме forward/backward. Нужны прогрев и корректная синхронизация GPU при замерах. В текущем уроке скорость не измеряется, оптимизированные fused attention kernels не используются.

Начни только с project_heads. После изменения определения класса заново создай экземпляр и перенеси веса; старый объект сам не получает новый код класса.

## 7. Разобранная ошибка: глобальные размеры в forward

В ученической реализации обратная сборка первоначально использовала reshape(B,T,D) с глобальными B=2,T=3. Первый тест проходил, но вход (1,1,8) содержал только 8 элементов, тогда как заданная форма (2,3,8) требовала 48.

Исправление: брать batch_size и length из текущего x.shape, а размер признаков — из self.d_model. Параметры слоя фиксированы, batch и длина входа могут меняться. Ошибка не требовала изменения математики attention.

Итог урока: текущий ученический код выполнен целиком в окружении deepschool. Совпали Q/K/V, выходы для нескольких B/T, градиенты входа и матриц; тест причинности прошёл. Это не замер ускорения и не обучение на текстовом корпусе.

Дальше используем проверенный слой при сборке Transformer-блока. Повторение индексов и autograd продолжим по ходу, не требуя сначала воспроизвести весь attention без подсказок.
