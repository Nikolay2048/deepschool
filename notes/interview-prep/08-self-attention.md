# Self-attention: от входного вектора до контекста

Практика: [notebook 03](../../Seminars/transformers/03-single-head-self-attention.ipynb).

Читай по частям: разделы 1–6 соответствуют остановке A; 7–9 — остановке B; 10–12 — остановке C. После каждого этапа закрой текст и восстанови смысл операций самостоятельно.

## 1. Где мы находимся

Мы реализовали путь: текст → token IDs → token embeddings + position embeddings → X.

Теперь реализуем: X → Q, K, V → scores → attention weights → context.

Вторая цепочка описывает одну голову self-attention. Это ещё не полный Transformer-блок: позже добавим выходную проекцию, residual connections, LayerNorm и MLP.

В этом уроке все позиции могут смотреть на все позиции своей последовательности. Для предсказания следующего токена добавим causal mask, иначе модель сможет подсматривать ответ.

## 2. Что лежит в X

В notebook один batch из B=2 последовательностей. В каждой T=3 позиции. D=4 — длина вектора позиции после embedding lookup.

| Объект | Форма | Как читать |
|---|---|---|
| Token embedding table | (V, D) | По одной строке на ID словаря |
| Position embedding table | (T_max, D) | По одной строке на допустимую позицию |
| Token IDs текущего batch | (B, T) | По одному целому ID на позицию |
| X текущего batch | (B, T, D) | По одному вектору на позицию |

В первой строке V означает размер словаря. Позже V традиционно обозначает тензор Values — это другое использование той же буквы.

Вход вычисляется так:

$$
X_{b,t}=E[\mathrm{token\_id}_{b,t}]+P[t]
$$

X[0,1] — вектор второго токена первой последовательности, форма (4,).
X[0] — все три вектора первой последовательности, форма (3,4).

Позиционная информация даёт сведения о месте токена. Она сама по себе не добавляет содержание соседних токенов. Если одинаковый ID стоит на одинаковой позиции в двух разных текстах, сумма E+P будет одинаковой при одинаковых таблицах.

Один ID на разных позициях получает разные суммы, потому что добавляются разные строки P.

## 3. Вспоминаем одну линейную проекцию

«Проекция» здесь означает обучаемое линейное преобразование. Оно не обязано уменьшать размерность или быть ортогональной проекцией из геометрии.

Рассмотрим вектор-строку:

$$
x=[1,2]
$$

Матрица весов слоя PyTorch:

$$
W=
\begin{bmatrix}
1 & 0\\
1 & 1
\end{bmatrix}
$$

Каждая строка W — веса одного выходного нейрона. Первый вычислит 1×1+0×2=1. Второй — 1×1+1×2=3. Поэтому:

$$
xW^T=[1,3]
$$

Это соответствует nn.Linear(2,2,bias=False) с указанными весами. Два входных числа превратились в два других.

Для D=4 слой содержит четыре выходных нейрона, каждый с четырьмя весами. Всего 16 параметров без bias. Каждый выход вычисляется по формуле:

$$
q_r=\sum_{c=0}^{D-1}W_{Q,r,c}x_c
$$

r — выходная координата, c — входная. Одна координата выхода может зависеть от всех координат входа.

## 4. Три преобразования одного токена

Мы создали три отдельных nn.Linear(D,D,bias=False). Они получают один X, но используют разные матрицы весов.

В наших обозначениях W_Q, W_K и W_V — матрицы .weight PyTorch. Поэтому:

$$
Q=XW_Q^T,\qquad K=XW_K^T,\qquad V=XW_V^T
$$

В статьях часто пишут Q=XW_Q без транспонирования: там W_Q определена в другой ориентации. Это соглашение об обозначениях. Здесь придерживаемся формата хранения PyTorch: (out_features,in_features).

Твой вариант Q = X @ query_projection.weight.T корректен при bias=False. Если включить bias, к произведению нужно добавить его. Вызов query_projection(X) делает это сам и использует стандартный механизм вызова модуля.

Одинаковая форма матриц не означает одинаковые значения. У них отдельные случайно инициализированные параметры. При обучении они получают градиенты через разные пути вычислений.

Если намеренно задать всем трём слоям одинаковые веса, при одном X их выходы совпадут. Названия Query/Key/Value сами по себе не заставляют числа различаться.

## 5. Зачем разделять Query, Key и Value

Attention решает две связанные задачи:

1. Вычислить, с какими весами брать информацию из каждой позиции.
2. Собрать эту информацию в новое представление.

Query и Key участвуют в первой задаче: их сравнение даёт score. Value участвует во второй: эти векторы смешиваются с найденными весами.

| Представление | Полезная метафора | Точная роль |
|---|---|---|
| Query | Что ищет получатель | Первый аргумент скалярного произведения |
| Key | Как найти источник | Второй аргумент скалярного произведения |
| Value | Что передаст источник | Вектор в итоговой взвешенной сумме |

Это не три заранее заданных лингвистических правила. Мы не говорим одному слою «ищи подлежащее», а другому «ищи глагол». Loss всей модели через backpropagation формирует полезные параметры.

Раздельные проекции позволяют обучать признаки для сопоставления и передачи информации отдельно. Базовое смешивание можно построить и без трёх обучаемых проекций; стандартная конструкция даёт модели больше гибкости.

Твой ответ «каждая кодирует свой сигнал» передаёт интуицию. На собеседовании дополни: отдельные веса создают разные представления, а роли этих представлений определяются местом в формуле attention.

## 6. Формы и параметры на остановке A

nn.Linear применяется к последнему измерению:

$$
(2,3,4)\ @\ (4,4)\ \longrightarrow\ (2,3,4)
$$

Одна матрица W_Q применяется ко всем шести векторам batch. Отдельный набор весов для каждого токена не создаётся.

Число параметров трёх проекций:

$$
3D^2=3\cdot4^2=48
$$

B и T определяют объём данных, а не число весов.

На этом этапе:

$$
Q[b,t]=f_Q(X[b,t])
$$

Другие позиции не используются при вычислении этой Query. Поэтому токены ещё не обменялись информацией.

**Самопроверка A:** для X формы (8,20,64) и проекций 64→64 назови форму Q и число параметров трёх слоёв без bias.

Ответ: (8,20,64) и 3×64×64=12288. Восстанови результат через число нейронов.

## 7. Сравниваем каждую Query с каждым Key

Для одной последовательности:

$$
s_{ij}=q_i\cdot k_j=\sum_r q_{i,r}k_{j,r}
$$

i — позиция получателя, j — позиция источника. Например:

$$
[1,2]\cdot[3,4]=1\cdot3+2\cdot4=11
$$

Score 11 ещё не вероятность. Он может быть отрицательным, нулевым или положительным. Скалярное произведение зависит и от направления, и от длины векторов; это не обязательно cosine similarity.

Для трёх позиций получится девять сравнений:

| | Key 0 | Key 1 | Key 2 |
|---|---|---|---|
| Query 0 | s00 | s01 | s02 |
| Query 1 | s10 | s11 | s12 |
| Query 2 | s20 | s21 | s22 |

Одна строка — сравнения одной Query со всеми Keys. На диагонали — сравнение с собственной позицией.

В коде: raw_scores = Q @ K.transpose(-2,-1).

$$
(B,T,D)\ @\ (B,D,T)\ \longrightarrow\ (B,T,T)
$$

Транспонируются только оси позиций и координат. Batch сохраняется: сравнения выполняются независимо для каждой последовательности.

Scores не обязаны быть симметричны: q_i·k_j и q_j·k_i — разные выражения.

## 8. Зачем делить на sqrt(d_k)

Скалярное произведение складывает d_k произведений координат. При независимых координатах с нулевым средним и единичной дисперсией дисперсия такой суммы равна d_k, а стандартное отклонение — sqrt(d_k).

Поэтому масштабируем:

$$
\widetilde S=\frac{QK^T}{\sqrt{d_k}}
$$

Это помогает не подавать в softmax чрезмерно большие по модулю scores, при которых распределение становится очень резким, а многие производные — маленькими. Объяснение опирается на указанные предположения; реальные обученные векторы не обязаны точно им соответствовать.

В нашем примере d_k=D=4, поэтому делим на 2. В multi-head attention d_k обычно будет размерностью одной головы, не всей модели.

## 9. Softmax превращает scores в веса

Для каждой строки:

$$
a_{ij}=\frac{\exp(\widetilde s_{ij})}{\sum_m\exp(\widetilde s_{im})}
$$

Одна Query распределяет единицу веса между доступными источниками. Например, одинаковые scores [0,0,0] превращаются в [1/3,1/3,1/3].

Вызов torch.softmax(scaled_scores,dim=-1) обрабатывает последнюю ось — Keys. Сумма каждой строки равна 1; сумма столбцов не обязана равняться 1.

Используем готовый softmax: он избегает переполнения экспонент посредством численно устойчивого вычисления.

Attention weights — вычисляемые для текущего входа коэффициенты. Они не являются постоянной таблицей параметров, в отличие от .weight линейных проекций.

**Самопроверка B:** что означает attention_weights[1,2,0]=0.7?

Ответ: во второй последовательности Query позиции 2 отдаёт вес 0.7 Value позиции 0.

## 10. Собираем информацию из Values

Пусть веса двух источников равны [0.25,0.75], а Values:

$$
v_0=[2,0],\qquad v_1=[0,4]
$$

Новое представление получателя:

$$
c=0.25v_0+0.75v_1=[0.5,3]
$$

Мы складываем векторы длины 2, поэтому длина результата тоже 2. Это не конкатенация.

Для всех позиций:

$$
C=AV,\qquad c_{b,i}=\sum_j a_{b,i,j}v_{b,j}
$$

В коде: context = attention_weights @ V.

$$
(B,T,T)\ @\ (B,T,D)\ \longrightarrow\ (B,T,D)
$$

В результате по-прежнему один вектор на позицию. Теперь он содержит взвешенную информацию из нескольких позиций. Именно здесь Values разных токенов смешиваются.

Одинаковый токен на одинаковой позиции в двух текстах имел одинаковое начальное X. После attention его представления могут различаться, потому что отличаются Keys и Values окружающих токенов. Это возможность, а не гарантия для любых весов и входов.

## 11. Что обучается и что пересчитывается

| Объект | Как появляется | Обновляется оптимизатором напрямую? |
|---|---|---|
| E, P, W_Q, W_K, W_V | Параметры слоёв | Да, если переданы оптимизатору |
| X, Q, K, V | Результаты forward | Нет |
| Scores и attention weights | Сравнения и softmax | Нет |
| Context | Взвешенная сумма | Нет |

Backward проходит через все эти операции к параметрам. При следующем forward промежуточные значения вычисляются заново с актуальными весами и входом.

В notebook probe_loss = context.square().mean() служит только для проверки градиентов. Это не loss обучения языковой модели. Для неё мы добавим предсказание следующего token ID и cross-entropy.

## 12. Границы текущей реализации

- Одна голова; пока d_k=d_v=D. В общем случае d_v может отличаться от d_k; размер выхода смешивания тогда будет d_v.
- Нет causal mask: будущие токены доступны. Пока это не готовая авторегрессионная модель.
- В примерах нет padding. Когда он появится, нужно исключить padding Keys из внимания и отдельно исключить padding targets из loss.
- Нет dropout; сумма строки attention weights после softmax равна 1. Attention dropout позднее меняет отдельные строки во время обучения.
- Параметры ещё не обучены. Распределение внимания не доказывает понимание языка.
- Positional embeddings не делают представления контекстными автоматически.
- Для обычного self-attention без позиционного сигнала и масок, задающих порядок, перестановка входов приводит к той же перестановке выходов. Это эквивариантность к перестановкам; выходы не обязаны оставаться на прежних местах.

## 13. Ответ для собеседования и повторение

> Self-attention создаёт представление каждой позиции как взвешенную сумму Value-векторов той же последовательности. Веса вычисляются сравнением Query этой позиции с Keys доступных позиций, масштабированием на sqrt(d_k) и softmax по Keys. Q, K и V получаются обучаемыми линейными проекциями входа. Параметры проекций общие для позиций и элементов batch, а attention weights зависят от конкретного входа.

Полная формула:

$$
\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

Не начинай ответ с одной формулы: сначала объясни получателя, источники и взвешенную сумму.

Для повторения без подсказок:

1. Восстанови путь от token IDs до context с формами всех тензоров.
2. Объясни, почему совпадение форм Q/K/V не означает равенства значений.
3. Посчитай один score вручную.
4. Объясни, по какой оси применить softmax.
5. Вычисли смесь двух Values с заданными весами.
6. Назови шаг, на котором токены начинают обмениваться содержимым.
7. Объясни, что запрещает будущая causal mask.

На следующем занятии начнём с causal mask. Через несколько занятий повторим пункты 1–3 на других B, T и D.

## 14. d_model, размер словаря и длина последовательности — разные вещи

В нашем notebook D означает d_model: длину основного вектора одной позиции. Это не число токенов в словаре и не размер контекстного окна. Координаты — обучаемые признаки; им не назначены заранее значения вроде «род» или «часть речи».

Например, vocab_size=10000, d_model=64, B=8, T=20:

```text
token_embedding.weight:  (10000, 64)
token_ids:                (8, 20)
X:                        (8, 20, 64)
```

Таблица содержит вектор для каждого ID словаря. Текущий X содержит только векторы позиций текущего batch.

Размеры проекций выбираются отдельно:

```python
query_projection = nn.Linear(d_model, d_k, bias=False)
key_projection = nn.Linear(d_model, d_k, bias=False)
value_projection = nn.Linear(d_model, d_v, bias=False)
```

| Объект | Форма |
|---|---|
| query_projection.weight | (d_k, d_model) |
| key_projection.weight | (d_k, d_model) |
| value_projection.weight | (d_v, d_model) |
| Q, K | (B, T, d_k) |
| V | (B, T, d_v) |
| Attention weights | (B, T, T) |
| Context | (B, T, d_v) |

Q и K должны иметь одинаковую последнюю размерность для скалярного произведения. Размер Value может отличаться: Values мы складываем с весами, а не сравниваем скалярным произведением с Q.

В уроке d_model=d_k=d_v=4 выбрано для наглядности. Матрицы не обязаны быть квадратными. Например, nn.Linear(4,2,bias=False) хранит weight формы (2,4) и преобразует X формы (8,20,4) в Q формы (8,20,2).

Размеры проекций напрямую не зависят от vocab_size, B или T. Увеличение T увеличивает число обрабатываемых векторов и размер матрицы внимания, но не число параметров проекции. В нашем варианте предел позиций задаёт таблица position_embedding, а не Query-проекция.

Общее число параметров трёх проекций без bias: d_model * (2*d_k + d_v). При равных размерностях это 3*D*D.

### Как выбирать размерности

Формы матриц — гиперпараметры архитектуры: их задаём до обучения. Обучение подбирает значения внутри, а не автоматически меняет формы.

Большая размерность даёт больше возможностей представления информации, но увеличивает память, вычисления и число параметров. Улучшение качества не гарантировано. Выбор проверяют на validation с учётом данных и вычислительного бюджета.

В стандартной multi-head конструкции часто d_k=d_v=d_model/число_голов: например, d_model=64 и 4 головы дают по 16 координат на голову. Это распространённое соглашение, а не единственная возможная архитектура. Вход и выход полного стандартного Transformer-блока обычно сохраняют d_model, хотя внутри размерности могут меняться.

## 15. Одна матрица для всех токенов и связь Value с токеном

Не путай слой и результат его работы:

```python
W = query_projection.weight  # общий обучаемый параметр
q_cat = X[0, 0] @ W.T        # результат на первом входном векторе
q_ate = X[0, 1] @ W.T        # результат на втором входном векторе
q_cheese = X[0, 2] @ W.T     # результат на третьем входном векторе
```

Разные входы проходят через одно правило. Отдельной Query-матрицы «для кота» нет. Вызов query_projection(X) выполняет это преобразование сразу для всех позиций всех последовательностей batch.

Value связан с токеном через всю цепочку вычислений:

```python
x_cat = token_embedding(cat_id) + position_embedding(position_id)
v_cat = value_projection(x_cat)
```

Value не берётся независимо от токена. Это преобразованный входной вектор. Пока параметры случайные, зависимость от токена уже есть, но полезное языковое содержание ещё не выучено.

Если x_cat изменится, v_cat может измениться даже при фиксированной Value-матрице. Не обязательно: например, нулевая матрица всегда даёт нулевой выход при bias=False.

Различай две операции:

```text
x @ W.T — матричное преобразование: каждая выходная координата
          есть скалярное произведение x с одной строкой W.

0.3 * v — умножение одного числа на каждую координату v:
          0.3 * [10,-2,4,8] = [3,-0.6,1.2,2.4].
```

Attention использует вторую операцию внутри взвешенной суммы. Затем складывает соответствующие координаты полученных векторов, а не склеивает векторы.

## 16. Raw scores: как не путать координату и позицию

Raw означает «исходные, необработанные». Последовательность вычислений:

```python
raw_scores = Q @ K.transpose(-2, -1)
scaled_scores = raw_scores / math.sqrt(Q.shape[-1])
attention_weights = torch.softmax(scaled_scores, dim=-1)
context = attention_weights @ V
```

| Обращение | Смысл последнего индекса |
|---|---|
| Q[0,1,2] | Координата 2 Query-вектора позиции 1 |
| raw_scores[0,1,2] | Позиция 2 Key, с которым сравнили Query позиции 1 |
| attention_weights[0,1,2] | Позиция 2 Value, чей вес для получателя 1 берём |
| context[0,1,2] | Координата 2 нового вектора позиции 1 |

Во всех строках 0 — первая последовательность batch. Индексация начинается с нуля.

В последовательности [кот, съел, сыр] raw_scores[0,1,2] сравнивает Query «съел» с Key «сыр». Это одно число: (Q[0,1]*K[0,2]).sum(). Последний индекс здесь не координата эмбеддинга, поскольку raw_scores имеет форму (B,T,T).

Сохранённый результат нашего запуска, округлённый:

| Query / Key | кот | съел | сыр |
|---|---:|---:|---:|
| кот | -1.941 | 1.661 | -0.651 |
| съел | -0.055 | -0.796 | 0.350 |
| сыр | -1.630 | 1.034 | 1.641 |

Для Query «съел» строка после деления на 2 и softmax даёт примерно [0.343,0.237,0.420]. Значит:

```python
# Приближённая запись с округлёнными весами:
context[0, 1] = 0.343*V[0, 0] + 0.237*V[0, 1] + 0.420*V[0, 2]
```

Raw scores могут быть отрицательными и не обязаны суммироваться в 1. Softmax нормирует строку, то есть источники для одной Query. Одинаковые scores без маски дают по 1/T на каждый источник, независимо от их общего значения: и [5,5,5], и [-5,-5,-5] дают [1/3,1/3,1/3].

Scores не обязаны быть симметричными. Коммутативность скалярного произведения означает q_i·k_j = k_j·q_i, но не q_j·k_i: во втором выражении другая пара векторов. В таблице score[1,2]=0.350, а score[2,1]=1.034.

## 17. Зачем всё это нужно и как матрицы обучаются

Один token embedding не различает значения слова «ключ» в текстах про замок и про решение задачи. Контекстные представления позволяют учитывать окружение. В causal-модели доступны только текущая и предыдущие позиции, поэтому информация из будущего в представление не попадает.

Можно просто усреднять все входные векторы, но тогда источники получают одинаковые веса. Attention позволяет весам зависеть от получателя и содержания конкретной последовательности.

Можно сравнивать X напрямую через X @ X.transpose(-2,-1). Раздельные Q/K-проекции дают дополнительный обучаемый способ сопоставления: важна не только похожесть исходных векторов, а полезность связи для задачи. Направление связи может иметь значение.

Можно смешивать X вместо V. Value-проекция даёт отдельное обучаемое преобразование передаваемого содержимого. Поэтому Q/K отвечают за вычисление весов смешивания, а V — за представление смешиваемой информации. Это удобная архитектура, а не единственная математическая возможность.

### От правильного следующего токена до обновления матриц

Пример: вход «Кошка подошла к миске и начала», правильное продолжение «есть». Для простоты считаем продолжение одним токеном.

1. Forward всей языковой модели вычисляет оценки токенов словаря через embeddings, attention и остальные слои.
2. Cross-entropy сравнивает предсказание с правильным token ID. Для одного правильного класса loss=-log(p_correct). На практике loss считают численно устойчиво непосредственно из logits, не через ручной log от вероятности.
3. loss.backward() вычисляет производные через выходные слои, context, Values и attention weights. Через softmax и scores градиенты доходят также до Q/K-проекций. Производные доходят и до эмбеддингов.
4. optimizer.step() обновляет переданные ему параметры. Для обычного SGD: parameter_new = parameter_old - learning_rate * gradient.
5. Следующий forward заново вычисляет Q/K/V и attention weights с актуальными параметрами.

Мы не задаём правильные Q, K, V или «идеальную матрицу внимания». Обучающий сигнал — правильный результат задачи. Градиент каждого параметра показывает локальную чувствительность loss к его изменению при фиксированных остальных параметрах.

Если увеличение веса некоторого источника в текущем вычислении уменьшило бы loss, эта зависимость может через производные повлиять на обновление Q/K-матриц. Содержимое передачи обучается через V-матрицу. Никакой отдельной словесной команды «смотри на существительное» нет.

Обновление не обязано улучшать каждый пример: параметры подбираются на множестве данных. Не гарантируется и конкретная человеческая интерпретация каждой головы или координаты.

В нашем notebook пока нет предсказаний словаря и optimizer.step(). Искусственный probe_loss=context.square().mean() лишь демонстрирует связность графа. Его минимизация сама по себе не учит языку.

### Формулировка для собеседования

> Формы Q/K/V-проекций задаются архитектурой, значения их параметров обучаются end-to-end по loss задачи. Backpropagation проходит через взвешенную сумму, softmax и скалярные произведения. Матрицы проекций общие для позиций, а attention weights вычисляются заново для конкретного входа. После обучения фиксированные параметры всё равно дают разное внимание на разных текстах.
