# Causal mask: как запретить подсматривание в будущее

Практика: [notebook 04](../../Seminars/transformers/04-causal-mask.ipynb). Предыдущая тема: [Self-attention](08-self-attention.md).

## 1. Зачем нужен запрет

При обучении языковой модели мы знаем весь учебный текст, но хотим научить модель предсказывать продолжение по доступному префиксу. Нельзя позволять ей использовать правильный ответ как часть входной информации для того же предсказания.

Пример с условной токенизацией по словам:

```text
Полный фрагмент: кот съел сыр <eos>
Входы:          кот съел сыр
Targets:        съел сыр <eos>
```

Выход позиции «кот» используется для предсказания «съел». Выход позиции «съел» — для предсказания «сыр». <eos> здесь условный токен конца текста, в текущий словарь notebook он не добавлен.

Если позиции «кот» разрешить прочитать входной токен «съел», у модели появится доступ к ответу. Низкий training loss при такой утечке не означает способность продолжать новый текст.

## 2. Правило доступности

Строка i матрицы attention соответствует Query получателя. Столбец j — Key/Value источника.

Источник разрешён, когда j <= i. Запрещён, когда j > i.

| Query / источник | кот: 0 | съел: 1 | сыр: 2 |
|---|---|---|---|
| кот: 0 | разрешён | запрещён | запрещён |
| съел: 1 | разрешён | разрешён | запрещён |
| сыр: 2 | разрешён | разрешён | разрешён |

Диагональ разрешена: текущий токен уже известен. Мы предсказываем следующий, а не пытаемся угадать текущий по нему самому. Проблема возникает, если targets ошибочно не сдвинуты относительно inputs.

## 3. Булева маска и broadcasting

В этом уроке blocked_mask[i,j] == True означает «запретить источник j для получателя i». Это соглашение для нашего вызова masked_fill, не универсальное правило любых API: при использовании другого готового attention всегда проверяй семантику его маски.

```python
positions = torch.arange(T, device=X.device)
query_positions = positions[:, None]  # (T,1)
key_positions = positions[None, :]    # (1,T)
blocked_mask = key_positions > query_positions  # (T,T)
```

None добавляет ось длины 1. Broadcasting сравнивает каждый номер источника с каждым номером получателя. Верхний треугольник строго выше диагонали получает True; диагональ и нижний треугольник — False.

Маска (T,T) применима ко всем B матрицам scores формы (B,T,T) через broadcasting. Это не смешивает последовательности. Маска зависит от позиций, а не от размера словаря или значений обучаемых весов.

## 4. Почему заполняем -inf до softmax

Softmax каждой строки делит экспоненту каждого score на сумму экспонент по источникам. exp(0)=1, поэтому нулевой score не запрещает внимание. Например, softmax([2,0,0]) всё ещё даёт ненулевые веса второму и третьему источникам.

Напротив, exp(-inf)=0. Если есть хотя бы один разрешённый конечный score, запрещённые позиции получают нулевой вес, а разрешённые нормируются до суммы 1.

```python
scaled_scores = (Q @ K.transpose(-2, -1)) / math.sqrt(Q.shape[-1])
masked_scores = scaled_scores.masked_fill(blocked_mask, float('-inf'))
attention_weights = torch.softmax(masked_scores, dim=-1)
context = attention_weights @ V
```

masked_fill возвращает тензор с заменёнными значениями под True. Q/K/V не изменяются этой операцией; маскируются связи между позициями.

Простое зануление запрещённых весов ПОСЛЕ softmax без повторной нормировки — другой расчёт: их масса уже участвовала в знаменателе, и сумма оставшихся весов обычно станет меньше 1. В уроке используем маскирование scores до softmax.

Не закрывай всю строку: softmax([-inf,-inf,-inf]) даёт NaN. В нашей простой causal mask диагональ всегда открыта. Совместную работу с padding и особыми пустыми строками рассмотрим отдельно.

## 5. Что меняется в результате

У первой позиции доступен один источник, поэтому её веса равны [1,0,0], а context[:,0] == V[:,0]. Это верно для нашего attention без dropout и последующих преобразований.

У второй позиции два источника: оба разрешённых веса зависят от scores, а третий равен нулю. У последней позиции разрешены все источники текущего входа.

Формы не изменяются:

```text
Q, K:              (B,T,d_k)
V:                 (B,T,d_v)
attention_weights: (B,T,T)
context:           (B,T,d_v)
```

Маска меняет доступ к содержимому, но не количество позиций на выходе.

## 6. Проверка причинности экспериментом

Возьми два X, одинаковых до последней позиции, и измени только последний вектор. При фиксированных параметрах causal attention предыдущие выходы должны совпасть: их Queries не изменились, разрешённые Keys и Values тоже, а изменившийся будущий источник запрещён.

```python
torch.testing.assert_close(before[:, :-1], after[:, :-1])
```

Это поведенческий тест: проверяем не только нули маски, но и отсутствие влияния будущего на результат. Без маски влияние возможно; ненулевое изменение не гарантируется для абсолютно любых параметров, например для нулевой Value-матрицы.

Тест предполагает, что до attention прошлые позиции X сами не получили информацию из будущего. Маска не может «вычистить» утечку, уже попавшую во входные представления через другую операцию.

В полном decoder-only Transformer причинность должна соблюдаться в каждом блоке. Позиционные преобразования вроде обычного Linear и LayerNorm по признакам одной позиции сами по себе не смешивают её с будущими позициями.

## 7. Параллельное обучение и последовательная генерация

На обучении все правильные входные токены уже есть. Мы одновременно вычисляем матрицу attention и применяем маску, поэтому все позиции могут обрабатываться параллельно без доступа к запрещённым источникам. Их предсказания сравниваются со сдвинутыми targets.

При авторегрессионной генерации следующий токен ещё неизвестен. Его нужно получить, добавить к входу и затем предсказать следующий. Эта зависимость между шагами генерации отличается от параллельного вычисления позиций внутри одного forward.

## 8. Короткий ответ для собеседования

> Causal mask запрещает Query позиции i использовать Keys/Values позиций j>i. Обычно запрещённые scores заменяют на -inf до softmax, поэтому их веса становятся нулевыми. Диагональ доступна: текущий токен известен, а target сдвинут на один вперёд. Маска предотвращает утечку будущего и позволяет вычислять все позиции параллельно при обучении.

Типичные ошибки: перепутать строки и столбцы, закрыть прошлое вместо будущего, закрыть диагональ без причины, заменить запрещённые scores нулями, не сдвинуть targets, маскировать только один блок из нескольких.
