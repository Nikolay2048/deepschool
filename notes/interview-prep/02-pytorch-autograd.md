# PyTorch: autograd и training loop

## 1. Четыре этапа обучения

```python
optimizer.zero_grad()
prediction = model(x)
loss = loss_fn(prediction, y)
loss.backward()
optimizer.step()
```

1. `zero_grad()` очищает накопленные градиенты.
2. Forward pass вычисляет значения и строит динамический граф.
3. `backward()` вычисляет градиенты loss по параметрам.
4. `step()` обновляет зарегистрированные в оптимизаторе параметры.

`backward()` не изменяет параметры, а `step()` не вычисляет градиенты.

## 2. Что происходит во время forward pass

PyTorch вычисляет численные значения и записывает историю отслеживаемых операций. Для backward он также может сохранять промежуточные значения, необходимые локальным производным.

Итоговые градиенты параметров во время forward pass ещё не вычисляются. Они появляются после `loss.backward()`.

```python
w = torch.tensor(2.0, requires_grad=True)
y = w ** 2

print(w.grad)  # None
y.backward()
print(w.grad)  # tensor(4.)
```

## 3. Leaf tensors и `grad_fn`

Тензор, созданный пользователем и не являющийся результатом отслеживаемой операции, является leaf tensor:

```python
w = torch.tensor(2.0, requires_grad=True)
y = w * 3

print(w.grad_fn)  # None: w не создан операцией графа
print(y.grad_fn)  # MulBackward...
```

По умолчанию `.grad` сохраняется у листовых тензоров с `requires_grad=True`. Промежуточному тензору для сохранения `.grad` нужен вызов `retain_grad()`.

## 4. Ветвление графа

Если параметр влияет на loss по нескольким путям, вклады производных складываются:

```python
y1 = w * x1
y2 = w * x2
loss = y1 + y2
```

$$
\frac{\partial L}{\partial w}
=
\frac{\partial L}{\partial y_1}\frac{\partial y_1}{\partial w}
+
\frac{\partial L}{\partial y_2}\frac{\partial y_2}{\partial w}
$$

Вдоль одного пути локальные производные перемножаются; вклады разных путей складываются.

## 5. Зачем нужен `torch.no_grad()`

`torch.no_grad()` временно отключает запись операций в autograd-граф:

```python
with torch.no_grad():
    w -= learning_rate * w.grad
```

Обновление параметров — действие алгоритма оптимизации, а не часть функции, производную которой вычисляет обычное обучение. Поэтому граф шага обновления строить не нужно. Кроме того, PyTorch защищает leaf tensor с `requires_grad=True` от отслеживаемого in-place изменения.

`no_grad()` не отключает вычисления: результат операции всё равно вычисляется. Отключается только её запись для последующего дифференцирования.

Для логирования обычно применяют:

```python
print(loss.item())
print(prediction.detach())
```

Операция, вычисленная только для печати и не использованная в loss, не меняет градиент loss. Однако без `no_grad()` она может создать ненужный временный граф.

## 6. Накопление градиентов

PyTorch прибавляет новые значения к `.grad`, а не заменяет их. В обычном training loop отсутствие очистки приводит к обновлению по сумме текущих и прошлых градиентов. Это меняет алгоритм и часто вызывает колебания или расходимость.

Накопление бывает намеренным при gradient accumulation по нескольким microbatches. Тогда loss обычно делят на число шагов накопления перед `backward()`.

### Можно ли очищать градиенты после `step()`

В простом цикле с одним `backward()` и одним `step()` на итерацию эти варианты эквивалентны:

```python
# Вариант 1: очистка перед вычислением новых градиентов
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

```python
# Вариант 2: очистка сразу после использования градиентов
loss.backward()
optimizer.step()
optimizer.zero_grad()
```

Во втором варианте обязательно выполнить первоначальную очистку перед первой итерацией, если `.grad` мог быть заполнен ранее. В учебном примере новые параметры имеют `.grad is None`, поэтому цикл работает корректно.

Первый вариант обычно читается безопаснее: непосредственно перед `backward()` видно, что градиенты относятся только к текущей итерации. При `continue`, исключении, условном `step()`, нескольких оптимизаторах или gradient accumulation положение очистки уже может менять поведение.

## 7. Линейная регрессия вручную

Для данных `y = 2x + 1`:

```python
x = torch.tensor([0.0, 1.0, 2.0, 3.0])
y = torch.tensor([1.0, 3.0, 5.0, 7.0])
w = torch.tensor(0.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)
```

На первой итерации при MSE и `lr = 0.05`:

$$
L=21,\qquad \frac{\partial L}{\partial w}=-17,
\qquad \frac{\partial L}{\partial b}=-8
$$

После шага:

$$
w=0.85,\qquad b=0.4
$$

После 100 эпох эксперимент дал `w = 2.0016`, `b = 0.9967`, что близко к истинным параметрам.

В реализации через `nn.Module`, `nn.Linear`, `nn.MSELoss` и `torch.optim.SGD` получены `w = 2.0071`, `b = 0.9849`; loss снизился с `45.307533` до `0.000151` на напечатанных эпохах. Другое начальное значение loss объясняется случайной инициализацией `nn.Linear`.

## 8. Большой learning rate и exploding gradients

При `lr = 0.5` loss и параметры стали быстро расти, затем появились `inf` и `nan`. Это расходимость оптимизации из-за слишком большого шага:

1. обновление перескакивает минимум;
2. следующая ошибка становится больше;
3. градиент также растёт;
4. колебания усиливаются;
5. значения переполняют диапазон `float32`, появляется `inf`;
6. последующие неопределённые операции приводят к `nan`.

Это не следует автоматически называть классическими exploding gradients. Обычно этот термин относится к росту градиентов при обратном проходе через много слоёв или временных шагов из-за произведения локальных производных. В эксперименте большие градиенты являются следствием расходящихся параметров и слишком большого learning rate.

## 9. Короткий ответ для собеседования

> Во время forward pass PyTorch вычисляет значения и строит динамический граф операций, сохраняя данные, необходимые для производных. `loss.backward()` выполняет reverse-mode autodiff и накапливает градиенты в `.grad` листовых тензоров. `optimizer.step()` читает градиенты зарегистрированных параметров и обновляет их. `torch.no_grad()` используют при обновлении или inference, чтобы операции не попадали в граф.
