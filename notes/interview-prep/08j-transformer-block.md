# Собираем pre-norm Transformer-блок

Практика: [06d-transformer-block.ipynb](../../Seminars/transformers/06d-transformer-block.ipynb).

## 1. Что мы собираем

Один decoder-only Transformer-блок принимает представления токенов (B,T,D) и возвращает новые представления той же формы. Это ещё не языковая модель: здесь нет превращения текста в token IDs, embeddings, выхода на словарь и генерации.

Берём готовые компоненты: causal multi-head attention из 05c, два LayerNorm, MLP из 06c и два residual-соединения. Attention не переписываем.

## 2. Две последовательные ветви

Точная запись с разными именами промежуточных результатов:

```python
a = attention(norm_1(x))
u = x + a
m = mlp(norm_2(u))
y = u + m
```

Все x, a, u, m, y имеют форму (B,T,D). Внутри attention временно появляются оси голов и матрица (T,T). Внутри MLP ширина расширяется до d_ff. Наружу оба модуля возвращают ширину D.

Эквивалентная компактная запись:

```python
x = x + attention(norm_1(x))
x = x + mlp(norm_2(x))
return x
```

Во второй строке x — уже результат первой строки. Это присваивание нового тензора переменной, не изменение исходного входа на месте через +=.

## 3. Почему именно такой порядок

Первая ветвь собирает доступный контекст через attention. Вторая нелинейно преобразует признаки уже обновлённого представления.

Нельзя заменять вторую строку на исходный вход x из начала блока, если мы хотим именно эту архитектуру. Запись y=x+attention(norm_1(x))+mlp(norm_2(x)) описывает параллельные ветви, а не наш последовательный блок.

Pre-norm означает, что LayerNorm находится перед преобразованием внутри ветви. Прямой residual-путь проходит без этой нормализации: складываем x с attention(norm_1(x)), а не norm_1(x) с attention(norm_1(x)).

Это выбранный вариант архитектуры, а не единственно возможный Transformer. Post-norm имеет иной порядок и здесь не реализуется.

## 4. Два независимых LayerNorm

norm_1 и norm_2 — два разных экземпляра nn.LayerNorm(D). У каждого собственные gamma и beta, поэтому вместе у них 4*D обучаемых чисел.

Первый работает с представлением до attention, второй — после первого residual-сложения. Их параметры не связаны: вызов одного и того же объекта два раза означал бы совместное использование параметров, что не соответствует выбранному блоку.

## 5. Что обучается и где хранится

В __init__ создаём дочерние модули и присваиваем self.norm_1, self.attention, self.norm_2, self.mlp. PyTorch регистрирует их параметры, поэтому block.parameters() возвращает и параметры attention, и MLP, и обоих LayerNorm.

Не создаём новые Linear в forward: тогда на каждом вызове появлялись бы новые слои вместо использования обучаемых параметров существующего блока.

Для нашей конфигурации D=8, H=2, d_ff=32:

- Attention: четыре матрицы 8*8 без bias — 256 параметров.
- MLP: 8*32+32+32*8+8 — 552 параметра.
- Два LayerNorm: 2*(8+8) — 32 параметра.
- Всего 840 параметров.

Residual-сложение и GELU собственных обучаемых параметров не имеют.

## 6. Почему блок остаётся причинным

Causal attention не использует будущие позиции. LayerNorm(D) и MLP обрабатывают текущую позицию отдельно. Residual складывает соответствующие позиции. Поэтому при изменении последнего входного токена более ранние выходы блока не должны меняться.

Важно, чтобы вход сам не содержал утечку будущего, добавленную до блока. Маска не убирает уже попавшую в представление информацию.

В учебном блоке пока нет dropout, поэтому сравнение двух forward не искажается случайными масками. Позже при наличии dropout такие сравнения обычно делают в eval.

## 7. Forward не означает обучение

Вызов y=block(x) вычисляет новые представления, но не обновляет параметры. Изменение входа между двумя вызовами — тоже не обучение.

Для обучения потребуется общий loss будущей языковой модели, затем zero_grad, backward и optimizer.step. Пока не добавляем искусственный тренировочный цикл: задача этого урока — правильно соединить уже понятные компоненты.

## 8. От блока к языковой модели

Следующий этап:

```text
token IDs → token embeddings + positional embeddings
          → Transformer-блок(и)
          → финальный LayerNorm
          → Linear(D, vocab_size)
          → logits следующего токена
```

Затем подготовим сдвинутые входы и targets, вычислим cross-entropy, запустим обучение на небольшом тексте и генерацию. Сам блок не выбирает следующий token ID: он выдаёт признаки для выходной проекции.

## 9. Короткий ответ для собеседования

> Наш pre-norm decoder-блок состоит из causal multi-head attention и position-wise MLP. Перед каждым преобразованием стоит свой LayerNorm, результат каждой ветви прибавляется к её входу. Блок сохраняет форму (B,T,D); MLP получает представление после attention-ветви. Причинность обеспечивается маской attention и отсутствием смешивания позиций в остальных операциях.
