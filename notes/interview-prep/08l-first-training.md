# Первое обучение Transformer и генерация текста

Практика: [08-first-training.ipynb](../../Seminars/transformers/08-first-training.ipynb).

## 1. Сегодня меняется не архитектура, а параметры

Модель из урока 07 уже умеет выполнять forward: token IDs → embeddings → блоки → logits. Но её параметры были случайными. Сегодня впервые многократно считаем ошибку и обновляем параметры, чтобы повысить вероятность правильного следующего токена.

Классы attention, блока и модели перенесены без изменений. Для запуска выбираем небольшую конфигурацию: D=32, H=4, d_ff=128, два блока, контекст 32 символа, batch 16, Adam с lr=0.001, 300 шагов. Это стартовый учебный опыт, не подбор оптимальных гиперпараметров и не обещание конкретной скорости или качества.

## 2. Почему теперь символы

Раньше словарь состоял из шести слов. Теперь каждый токен — один символ: русская буква, пробел, точка или перевод строки. Можно собирать новые слова, не добавляя каждое слово в словарь. Цена — более длинные последовательности.

Алфавит фиксирован заранее: 33 русские буквы, пробел, точка, перевод строки; всего 36 токенов. Некоторые символы не встречаются в train, и модель не научится осмысленно их использовать только из-за наличия в таблице. Заглавные буквы и неизвестные знаки в prompt вызывают понятную ошибку, а не молча удаляются.

encode превращает строку в список ID; decode делает обратное. Никаких весов токенизатора здесь нет. Embedding по-прежнему обучается внутри модели.

## 3. Откуда данные и что означает validation

В ноутбуке создаётся синтетический корпус по явно заданному шаблону:

```text
утром {герой} гулял {место}. потом он {действие}. вечером {герой} вернулся домой.
```

Шесть героев, четыре места и пять действий дают 120 историй. Их перемешиваем с фиксированным seed и делим на 108 train и 12 validation историй. Это специально простая задача для первого запуска, не внешний корпус и не тест знания русского языка.

Сначала делим целые истории, затем собираем отдельные train/val потоки и создаём окна внутри каждой части. Так одно перекрывающееся окно не попадает в train, а соседнее из того же исходного участка — в validation.

Однако фразы и общий шаблон сильно повторяются между частями. Validation показывает перенос на отложенные сочетания знакомых элементов, но не качество на независимых жанрах. Для серьёзной оценки нужен отдельный разнообразный корпус и test, которого здесь пока нет.

## 4. Как из текста получается batch

Для окна длины T нужны T+1 исходных символов. Например, при T=3:

```text
Исходный участок: к о т .
Вход:             к о т
Target:           о т .
```

Пробелы между символами в схеме — разделители, не часть примера.

Для каждой позиции target — следующий символ. get_batch случайно выбирает B начальных индексов и собирает B окон. Формы x и y: (B,T), dtype long.

Последний допустимый старт равен len(data)-T-1: после T входных символов должен остаться ещё один для последнего target. Поэтому torch.randint(len(data)-T, ...) корректен: верхняя граница исключена.

Окна могут пересекаться внутри train; это допустимо. В нашем потоке они могут также пересекать перевод строки между историями. Шаг цикла — обработка одного batch и обновление параметров. Это не эпоха: полного последовательного обхода корпуса здесь нет.

## 5. Forward и ошибка

```python
logits = model(x)  # (B,T,V)
loss = F.cross_entropy(
    logits.reshape(-1, V),
    y.reshape(-1),
)
```

V=36 — размер словаря символов. reshape превращает B*T позиций в список примеров. Для каждой позиции есть V оценок и один правильный ID. Порядок сохраняется, соответствие целей и оценок не нарушается.

Для одной позиции ошибка равна -ln(p правильного символа). При равномерном распределении p=1/V получаем ln(V). Это ориентир для равномерного предсказания, не обязательное начальное значение случайной сети. Cross-entropy получает logits, не предварительный softmax.

## 6. Три команды, которые нужно восстановить

```python
optimizer.zero_grad(set_to_none=True)
logits = model(x)
loss = ...
loss.backward()
optimizer.step()
```

zero_grad очищает накопленные градиенты. С set_to_none=True они обычно становятся None, а не заполняются нулями; параметры не меняются.

backward вычисляет производные loss по параметрам и накапливает их в .grad. Проход идёт через всю модель: выходную проекцию, нормализации, MLP, attention и embeddings.

step обновляет параметры с использованием градиентов. Adam использует также внутреннее состояние, связанное с прошлыми градиентами; это не просто чистый SGD. Подробную формулу Adam разберём отдельно.

Нельзя оборачивать обучающий forward в no_grad: для backward нужен граф. model.train() сам по себе градиенты не вычисляет. Без step обучение параметров не произойдёт; без backward после очистки не будет новых градиентов для обновления.

В текущей практике три NotImplementedError намеренно заменяются этими вызовами. Не просто удаляй их: иначе цикл может выглядеть работающим без реального обучения.

## 7. Как измеряем прогресс

Перед первым обновлением и через каждые 50 шагов считаем train и validation loss на фиксированных наборах случайно выбранных окон. Это выборочная оценка, не полный проход по каждой части данных.

При каждом измерении создаются генераторы с одинаковыми seed: набор оценочных окон повторяется. Они не влияют на генератор, выбирающий обучающие batch. Так изменение оценочного loss связано с параметрами, а не с новой случайной выборкой окон.

Все batch оценки равного размера, и padding нет. Поэтому простое среднее их средних loss корректно для выбранных позиций. Если размеры различаются, нужно взвешивать по числу позиций.

Оценку выполняем в eval и no_grad, затем восстанавливаем предыдущий режим. В этой архитектуре нет dropout, но разделение обучения и оценки полезно сохранить. eval не заменяет no_grad и не запрещает ручную запись в параметры.

В логе step_loss — ошибка обучающего batch до текущего обновления. train/val — оценки после него. Не требуем равенства этих чисел.

Ожидаем тенденцию уменьшения ошибки, не строгое падение на каждом шаге. Снижение train при росте validation может указывать на переобучение, но маленький набор оценки и изменение оптимизации тоже нужно учитывать. Один текст и одна цифра не достаточны для вывода о качестве.

## 8. Как генерируется продолжение

Для prompt «утром кот »:

1. Кодируем prompt в ID и создаём форму (1,T).
2. Подаём доступный контекст модели.
3. Берём logits только последней позиции: это оценки следующего символа после всего контекста.
4. Применяем softmax и выбираем один ID из полученного распределения.
5. Дописываем выбранный ID к последовательности.
6. Повторяем.

```python
context = ids[:, -model.max_seq_len:]
logits = model(context)
probabilities = softmax(logits[:, -1, :] / temperature)
next_id = sample(probabilities)
ids = cat([ids, next_id], dim=1)
```

В коде выбор выполняет torch.multinomial. Это случайный выбор с указанными вероятностями, а не обязательно максимальный логит. temperature=1 оставляет распределение без изменения. Настройки sampling разберём позже.

При обучении модель получает настоящие предыдущие символы из корпуса. При генерации она получает собственные прошлые выборы и может накапливать ошибки. Targets при генерации отсутствуют, параметры не обновляются.

Когда текст длиннее max_seq_len, оставляем последние 32 символа. В этой простой реализации позиционные ID заново идут от 0 в каждом окне и весь forward считается повторно. KV-cache нет. Функция возвращает весь накопленный текст, хотя модель каждый раз видит только последний участок.

Количество новых символов фиксировано. Нет EOS-токена и автоматического решения «история закончена». Точка — обычный токен.

## 9. Сравнение до и после

Сохраняем before_text до первого обновления, затем after_text после цикла. Используем одинаковые prompt, seed sampling, temperature и число новых токенов.

Результаты не обязаны быть одинаковыми: изменились параметры и вероятности. Равный seed помогает удержать настройки сравнения, но не превращает одну генерацию в надёжную оценку.

Первый успех — наблюдаемое уменьшение ошибки и появление знакомых сочетаний символов. Идеальная грамматика не обязательна. Если после 300 шагов вывод плохой, сначала смотрим loss и реальное выполнение backward/step, а не объявляем модель или обучение бесполезными.

## 10. Что может запутать в Jupyter

- Ячейка создания model и optimizer сбрасывает прогресс. Повтор только цикла продолжает обучение.
- steps_done показывает суммарное число обновлений, history хранит замеры. TRAIN_STEPS — число новых шагов одного запуска цикла.
- Прерывание цикла оставляет уже выполненные обновления в памяти. Счётчик при прерывании ровно во время операции может не отражать этот незавершённый шаг.
- Restart Kernel удаляет модель из памяти. Автоматического сохранения весов на диск в этом уроке нет.
- Для чистого воспроизведения сначала заполни train_step, затем Restart Kernel → Run All → сохранить outputs.
- inf/nan — повод остановиться и разобраться, не продолжать сотни шагов. Защита в train_step прекращает такой запуск.
- Если медленно, пришли устройство и время первых шагов. По ним выберем объём работы. Скорость заранее не измерялась.
