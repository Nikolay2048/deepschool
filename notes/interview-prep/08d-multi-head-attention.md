# Multi-head attention: несколько способов собрать контекст

Практика: [notebook 05](../../Seminars/transformers/05-multi-head-attention.ipynb). Основа: [attention как nn.Module](08c-attention-module.md).

## 1. Зачем несколько голов

Одна голова вычисляет одну строку весов для каждой Query и с этими коэффициентами смешивает все координаты своих Values. Это один способ распределить внимание между источниками для данной позиции.

Несколько голов имеют разные Q/K/V-проекции и могут получить разные распределения внимания на одном входе. Результаты сохраняем отдельно до объединения, чтобы модель могла использовать несколько способов сбора информации.

Мы не назначаем голове роль «грамматика» или «смысл». Полезные особенности могут возникнуть при совместном обучении по loss задачи; разнообразие и качество не гарантированы одним только числом голов. Пока параметры случайные, картинки внимания не доказывают языковую специализацию.

## 2. Каждая голова видит весь вход

Выберем d_model=D=4, num_heads=H=2 и head_dim=D/H=2.

Каждая голова получает X формы (B,T,4). У каждой три своих Linear(4,2,bias=False), то есть по три матрицы (2,4). Все четыре координаты входа могут влиять на каждую выходную координату. Голова не получает заранее отрезанную половину исходного эмбеддинга.

```python
head_0 = CausalAttentionHead(d_model=4, head_dim=2)
head_1 = CausalAttentionHead(d_model=4, head_dim=2)
output_0 = head_0(x)
output_1 = head_1(x)
```

Два отдельных конструктора создают независимые параметры. Одинаковая форма матриц не означает равенства чисел.

Вариант H голов с выходом D каждая также возможен, но тогда общая размерность после склейки будет H*D и параметров станет больше. В этом уроке используем стандартное разбиение общей ширины D между головами: H*head_dim=D.

## 3. Формы одной головы

| Тензор | Форма при B=2, T=3, D=4, H=2 |
|---|---|
| Общий вход X | (2,3,4) |
| Weight каждой Q/K/V-проекции одной головы | (2,4) |
| Q/K/V одной головы | (2,3,2) |
| Scores и веса внимания одной головы | (2,3,3) |
| Выход одной головы | (2,3,2) |

Число позиций T не изменилось. Изменилось число признаков в Q/K/V. Масштаб scores — sqrt(head_dim), здесь sqrt(2), а не sqrt(D)=2.

Каждая голова применяет свою softmax к собственным scores. Causal mask одинакова по правилу j>i, но разрешённые веса у голов могут различаться. Последовательности batch не смешиваются.

## 4. Объединение: cat, не сумма

Пусть для одной позиции первая голова дала [1,2], вторая — [10,20].

```text
Сумма:        [11,22]
Конкатенация: [1,2,10,20]
```

Сумма сразу смешивает соответствующие координаты с фиксированными коэффициентами 1. Конкатенация сохраняет обе группы признаков, чтобы следующее обучаемое преобразование могло смешать их по-разному.

```python
combined = torch.cat([output_0, output_1], dim=-1)
```

Форма: два тензора (B,T,2) превращаются в один (B,T,4). Мы не удваиваем batch или длину последовательности. Первые две координаты каждой позиции — результат первой головы, следующие две — второй.

torch.stack добавил бы новую ось, например (B,T,H,head_dim) при подходящем dim. Пока эту ось явно не создаём. При векторизации введём ось H, но сохраним тот же смысл вычислений.

## 5. Зачем выходная проекция

```python
output_projection = nn.Linear(D, D, bias=False)
result = output_projection(combined)
```

После cat группы признаков стоят рядом. Выходная проекция обучается составлять из них новые сочетания: каждая выходная координата может зависеть от координат всех голов. Одинаковая размерность входа/выхода не означает отсутствие преобразования.

Она применяется независимо к каждой позиции и не добавляет доступ к будущему. Если выходы голов причинны, это позиционное преобразование сохраняет причинность.

Это ещё не Transformer-блок: residual, LayerNorm и MLP добавим отдельно.

## 6. ModuleList и независимые параметры

```python
self.heads = nn.ModuleList([
    CausalAttentionHead(d_model, head_dim)
    for _ in range(num_heads)
])
```

ModuleList регистрирует все дочерние головы. Тогда model.parameters(), model.to(...) и state_dict учитывают их проекции. Обычный list с модулями сам по себе не регистрирует свои элементы в родительском nn.Module.

ModuleList — контейнер, не готовый вычислительный конвейер. В forward перебираем головы и подаём каждой один и тот же x:

```python
head_outputs = [head(x) for head in self.heads]
combined = torch.cat(head_outputs, dim=-1)
return self.output_projection(combined)
```

Не используй [head] * H для независимых голов: это H ссылок на один объект с общими параметрами. Если обеим таким «головам» подать один x без случайных операций, результаты совпадут.

## 7. Число параметров

Без bias одна голова содержит 3*D*head_dim параметров. Для H голов при head_dim=D/H сумма равна 3*D*D. Выходная проекция добавляет D*D. Всего 4*D*D.

Для D=4, H=2:

```text
Одна голова:       3*4*2 = 24
Две головы:       2*24  = 48
Выходная проекция: 4*4  = 16
Всего:                  64
```

При фиксированном D число параметров этой конструкции не зависит от H, если D делится на H. Но организация вычислений меняется; в явной реализации хранятся H матриц внимания (B,T,T), поэтому потребление памяти на attention weights зависит от H. Не путай неизменное число параметров с неизменными затратами памяти и времени.

У прошлого single-head слоя было 48 параметров без выходной проекции. Здесь 64 из-за добавленной выходной проекции; это не корректное сравнение «параметры выросли из-за двух голов».

## 8. Обучение и проверки

Градиенты от общего loss проходят через выходную проекцию и cat к каждой голове, затем через её attention к Q/K/V-матрицам. Cat не обрывает граф. Все зарегистрированные параметры можно передать одному оптимизатору.

Проверяем формы, независимость голов, совпадение явного вычисления, число параметров, причинность и конечные градиенты. Для T=1 attention равен 1 независимо от scores, поэтому Q/K могут получить нулевой градиент; это не обязательно ошибка.

Тесты не доказывают понимание языка и не гарантируют, что головы выучат разные полезные связи. Для этого нужны обучение на задаче и оценка на отдельных данных.

## 9. Следующая ступень: векторизация

Сегодня головы представлены отдельными объектами и вызовами в Python. Позже объединим проекции и введём форму (B,H,T,head_dim), чтобы выполнять операции по головам в объединённых тензорах. Исходный X по-прежнему не режется на независимые куски до проекции: разделяются выходные координаты обучаемого преобразования.

Сначала проверим совпадение двух реализаций на одинаковых параметрах. Не заявляем ускорение без измерений.

## 10. Ответ для собеседования

> Multi-head attention использует несколько наборов Q/K/V-проекций на одном входе. Каждая голова вычисляет собственные веса внимания и смесь Values. Результаты конкатенируются по признакам и проходят выходную линейную проекцию. В стандартном варианте head_dim=d_model/num_heads; деление scores идёт на sqrt(head_dim). При фиксированном d_model и без bias число параметров вместе с выходной проекцией равно 4*d_model².

## 11. Разбор срезов в проверке причинности

Для x формы (2,3,4) запятые разделяют выбор по осям, а двоеточие задаёт диапазон внутри одной оси. Срез не отбрасывает следующие оси. Неуказанные оставшиеся оси берутся целиком.

| Выражение | Выбор | Форма |
|---|---|---|
| x[:, :-1] | Все позиции, кроме последней | (2,2,4) |
| x[:, -1] | Последняя позиция, ось T убрана | (2,4) |
| x[:, -1:] | Последняя позиция, ось T сохранена | (2,1,4) |
| x[:, :1] | Только первая позиция, ось T сохранена | (2,1,4) |
| x[:, :2, :] | Первые две позиции, все признаки | (2,2,4) |

Срез начало:конец не включает правую границу. Целочисленный индекс убирает выбранную ось, а срез сохраняет её. Поэтому x[:, :1] эквивалентно x[:, :1, :], но не x[:,0].

В тесте меняем changed[:, -1], то есть последний входной токен каждой последовательности. Сравниваем model(x)[:, :-1] и model(changed)[:, :-1], то есть все прошлые выходы. Их совпадение проверяет отсутствие влияния изменённого будущего на прошлое.
