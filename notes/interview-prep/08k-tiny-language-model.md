# Tiny decoder-only LM: от token IDs до logits

Практика: [07-tiny-language-model.ipynb](../../Seminars/transformers/07-tiny-language-model.ipynb).

## 1. Что добавляем к готовому блоку

Наш блок принимает векторы (B,T,D), а пользователь даёт текст. Кроме того, блок возвращает признаки, а нам нужны оценки возможных следующих токенов. Добавим входные embeddings и выходную проекцию:

```text
token IDs (B,T)
→ token embeddings + positional embeddings (B,T,D)
→ Transformer-блок(и) (B,T,D)
→ финальный LayerNorm (B,T,D)
→ Linear(D,V) (B,T,V)
```

V — размер словаря. Выход — logits: по одному числу для каждого кандидата из словаря на каждой позиции. Это не вероятности и не сами token IDs.

Сегодня собираем модель и разбираем цель обучения. Обучение на тексте и генерацию сделаем следующим этапом. Необученная модель не обязана выдавать осмысленные предсказания.

## 2. Вход: целочисленные идентификаторы

Embedding(V,D) хранит обучаемую таблицу V строк по D чисел. Token ID выбирает строку. Для входа (B,T) получаем (B,T,D). В PyTorch используем torch.long.

Для первого примера используем маленький явно заданный словарь слов, а не внешний токенизатор. Это учебная иллюстрация, не полноценная токенизация произвольного текста. На следующем этапе для небольшого корпуса можно взять посимвольную токенизацию.

## 3. Позиции

Learned positional embedding — отдельная таблица (max_seq_len,D). Для входа длины T выбираем позиции от 0 до T-1:

```python
positions = torch.arange(T, device=token_ids.device)
x = token_embedding(token_ids) + position_embedding(positions)
```

Первое слагаемое имеет форму (B,T,D), второе — (T,D). Broadcasting использует одни и те же векторы позиций во всех последовательностях batch. Это сложение, а не склеивание.

T может меняться между вызовами, но не превышать размер таблицы max_seq_len. B этой таблицей не фиксируется. Большое max_seq_len само по себе не означает, что модель научилась работать с длинным контекстом.

## 4. Один или несколько блоков

Несколько блоков применяются последовательно. У каждого свои параметры: второй блок обрабатывает выход первого, а не исходные embeddings. В ноутбуке готовый ModuleList и цикл, для первого запуска n_layers=1.

Не используем [block]*n_layers: это повторяет ссылки на один объект и разделяет веса. Здесь каждый экземпляр создаётся отдельно.

Финальный LayerNorm нормализует выход всей цепочки pre-norm блоков. Это ещё один отдельный набор gamma/beta, не замена нормализаций внутри блоков.

## 5. Выходная проекция

lm_head = nn.Linear(D,V,bias=False) создаёт V оценок из D признаков каждого токена. Её weight имеет форму (V,D), параметров V*D.

В нашем варианте её веса независимы от таблицы token embeddings, хотя формы совпадают. Связывание этих весов (weight tying) — возможный отдельный выбор архитектуры, сейчас его нет.

Для B=1, T=3, V=6 получаем logits.shape == (1,3,6).

- logits[0,0] — оценки токена после первого входного токена;
- logits[0,1] — оценки после первых двух;
- logits[0,2] — оценки после первых трёх.

Это возможно за один forward благодаря causal mask. Выход в позиции t предсказывает токен t+1, имея доступ к входам до t включительно.

## 6. Как задаётся задача предсказания

Полная учебная последовательность: «кот ест рыбу .».

```text
Вход:     кот   ест   рыбу
Target:   ест   рыбу  .
```

Для full_ids формы (B,T+1):

```python
inputs = full_ids[:, :-1]
targets = full_ids[:, 1:]
```

Вход и target имеют одинаковую форму (B,T), но target сдвинут на одну позицию. Не просим модель просто копировать токен текущей позиции. Последний target не подаётся как вход последней позиции.

Хотя «ест» уже присутствует в inputs на второй позиции, первая позиция его не видит из-за causal mask.

## 7. Logits, вероятности и loss

Чтобы посмотреть распределение последующего токена:

```python
probabilities = torch.softmax(logits[:, -1, :], dim=-1)
```

Форма (B,V). Последняя ось теперь словарь, а не признаки embeddings и не позиции attention.

Для обучения используем cross-entropy по logits, без предварительного softmax:

```python
loss = F.cross_entropy(
    logits.reshape(-1, vocab_size),  # (B*T,V)
    targets.reshape(-1),             # (B*T,)
)
```

Reshape здесь превращает позиции batch в список обучающих примеров, сохраняя соответствие logits и targets. Cross-entropy учитывает нормализацию logits численно устойчивым способом. Для одной позиции loss = -log(p правильного токена); по умолчанию усредняем по всем позициям без padding в этом примере.

Сегодня считаем loss, но не вызываем backward/step. Одно вычисление ошибки не является обучением. Не требуем заранее определённого значения: оно зависит от случайных параметров.

## 8. Чего пока нет

Нет корпуса, разделения train/validation, цикла обучения, генерации или замеров качества. В примере нет padding, поэтому отдельная маска padding не нужна. Позиции каждый вызов начинаются с нуля; KV-cache не реализуем.

Следующий урок: небольшой текст, посимвольный словарь, сдвинутые окна, обучение и генерация по одному токену. Сначала добьёмся работающего минимального цикла, затем улучшим оценку качества и эксперименты.

## 9. Короткий ответ

> Decoder-only LM преобразует token IDs в embeddings с позиционной информацией, обрабатывает их causal Transformer-блоками и проецирует признаки в logits по словарю. На каждой позиции предсказывается следующий токен. При обучении targets сдвинуты на один шаг, а cross-entropy получает logits, не готовые вероятности.
