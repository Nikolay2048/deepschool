# Собственный attention как nn.Module

Практика: [notebook 04b](../../Seminars/transformers/04b-attention-module.ipynb). Предыдущая тема: [Causal mask](08b-causal-mask.md).

## 1. Что меняется относительно функции attend

Математика остаётся прежней: Q/K/V → scaled scores → causal mask → softmax → сумма Values. Меняется организация кода. Раньше функция использовала три слоя из внешних переменных. Теперь объект будет хранить свои проекции и применять их к переданному входу.

Это позволяет создавать независимые экземпляры, получать все параметры одним вызовом, переносить их на устройство и копировать состояние. Модуль сам по себе не означает обучение: нужны loss, backward и optimizer.step.

## 2. Минимальный пример

```python
class TokenProjection(nn.Module):
    def __init__(self, in_features, out_features):
        super().__init__()
        self.projection = nn.Linear(in_features, out_features, bias=False)

    def forward(self, x):
        return self.projection(x)

model = TokenProjection(4, 2)
y = model(x)
```

`self` — конкретный экземпляр класса. `self.projection` — слой, принадлежащий этому экземпляру. Два независимых вызова конструктора обычно создают разные параметры.

`super().__init__()` инициализирует внутреннюю структуру nn.Module. Вызываем его до присваивания дочерних модулей: PyTorch должен иметь возможность зарегистрировать их.

## 3. __init__ и forward решают разные задачи

В __init__ создаём и сохраняем обучаемые слои. Метод выполняется при создании экземпляра. В forward вычисляем результат очередного входа с уже существующими параметрами.

Не создавай новый nn.Linear при каждом forward: это создаёт новые параметры вместо повторного использования обучаемых. Локально созданный слой также не появляется автоматически среди параметров родительского модуля. Даже присваивание нового слоя self внутри forward заменяет старый слой; ранее созданный оптимизатор может продолжить хранить ссылки на старые параметры.

Маску, напротив, можно создавать в forward: это не обучаемые веса, а правило j > i для текущей длины входа.

## 4. Регистрация параметров

Присваивание `self.query_projection = nn.Linear(...)` регистрирует дочерний модуль. Его weight — nn.Parameter. Поэтому родительский `model.parameters()` рекурсивно находит веса дочерних слоёв.

```python
for name, parameter in model.named_parameters():
    print(name, parameter.shape)
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)
```

Для трёх проекций 4→4 без bias ожидаем три матрицы (4,4) и 48 параметров. B и T не входят в число параметров.

Обычный тензор, присвоенный self, не становится обучаемым параметром автоматически. Для собственного обучаемого тензора используют nn.Parameter; для необучаемого состояния, которое должно перемещаться вместе с моделью, — register_buffer. Буферы изучим отдельно. В этом уроке достаточно nn.Linear.

## 5. Параметры и промежуточные результаты

`self.query_projection.weight` существует между вызовами forward. `q = self.query_projection(x)` — результат на текущем входе. Q/K/V, scores и context заново вычисляются при каждом вызове; их не нужно хранить как параметры.

Вызывай `model(x)`, а не напрямую `model.forward(x)`: стандартный вызов nn.Module выполняет forward через механизм вызова модуля, включая зарегистрированные hooks. В простом примере числа могут совпасть, но прямой вызов forward обходит этот механизм.

Ни model(x), ни model.train() не выполняют optimizer.step(). Режим train/eval и включение autograd — разные настройки. В текущем слое нет dropout или других операций, зависящих от train/eval.

## 6. Контракт нашего слоя

Вход — готовые представления X формы (B,T,d_model), не token IDs. Эмбеддинги будут частью внешней языковой модели. Выход — context такой же формы, поскольку в уроке d_k=d_v=d_model.

Одна голова, causal mask, нет bias, padding, dropout и выходной проекции. Это не весь Transformer-блок.

Длину T берём из x.shape[1], устройство маски — из x.device. Поэтому один экземпляр обрабатывает разные B и T. На GPU нужно перенести и модель, и вход; одно только правильное устройство маски не переносит проекции.

Маску создаём на каждом forward. Это прозрачный учебный вариант, а не утверждение о максимальной производительности. Позже можно рассмотреть буфер максимальной длины или готовые оптимизированные операции.

## 7. Что проверяем

1. Три независимые зарегистрированные проекции и 48 параметров.
2. Совпадение с явным attention на тех же весах. Два случайно созданных слоя без копирования весов сравнивать на равенство выходов нельзя.
3. Разные B/T, включая T=1; первая позиция равна её Value.
4. Причинность: изменение будущего не влияет на предыдущие выходы.
5. Конечные градиенты у параметров после искусственного loss.
6. Изменение хотя бы одного параметра после шага SGD.
7. Совпадение выходов после переноса state_dict в другой экземпляр.

Проверка одного шага на искусственном loss не означает обучение языковой модели или гарантированное улучшение качества. Для языка нужны выходные logits, сдвинутые targets, cross-entropy и данные.

## 8. state_dict

state_dict содержит параметры и persistent buffers модели, но не локальные активации q/k/v. load_state_dict загружает состояние в совместимую архитектуру; саму архитектуру нужно создать отдельно.

В упражнении копируем состояние в памяти, не создаём checkpoint-файл. Для настоящего возобновления обучения обычно нужны также состояние оптимизатора и другие сведения о запуске.

## 9. Ответ для собеседования

> nn.Module объединяет параметры и вычисление. Дочерние слои создаю в __init__ после super().__init__, а в forward применяю их к входу. Регистрация позволяет получить параметры через parameters(), перемещать модуль и работать со state_dict. Attention-матрицы текущего входа — промежуточные результаты, не параметры. Маска строится по длине входа и применяется до softmax.

Сегодня выполняем только остановку A: знакомство с модулем и регистрация трёх проекций. После разбора переносим forward, затем запускаем проверки.
